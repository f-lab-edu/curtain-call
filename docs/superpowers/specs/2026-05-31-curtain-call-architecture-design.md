# 커튼콜(Curtain Call) 아키텍처 설계 초안

- 작성일: 2026-05-31
- 문서 성격: 전체 아키텍처 개요 (초안). 도메인별 상세 spec/plan은 본 문서 이후 분리하여 작성한다.
- 프로젝트 목적: **학습용**. 실서비스 운영이 아닌, 아래 4개 영역의 깊이 있는 학습이 목표.

## 1. 프로젝트 개요

- 주제: 공연 검색 및 예매 플랫폼
- 기술 스택: Java 17, Spring Boot 3.4.8, MySQL, MyBatis, Spring Security
- 추가 인프라: Redis, Elasticsearch, Nginx, ELK(또는 Loki+Grafana), Docker Compose

### 학습 목표 (이 프로젝트의 핵심)

1. **인증/인가** — 세션 + Redis 기반
2. **예매 시 동시성 처리** — 좌석 선점(Hold) 방식
3. **AI 자연어 검색/추천** — 벡터 임베딩 시맨틱 검색
4. **분산 인프라 + 로깅** — 앱 다중화 + LB + DB 레플리카 + 중앙 로깅

## 2. 시스템 구성도

```
            ┌───────────┐
   Client → │  Nginx LB │
            └─────┬─────┘
          ┌───────┴────────┐
     ┌────▼────┐      ┌────▼────┐      Spring Boot 앱 (무상태)
     │  app#1  │  …   │  app#N  │      세션/선점 상태는 외부화
     └────┬────┘      └────┬────┘
          └───────┬────────┘
        ┌─────────┼──────────────┬─────────────┐
   ┌────▼───┐ ┌───▼─────┐ ┌──────▼──────┐ ┌────▼────────┐
   │ Redis  │ │ MySQL   │ │Elasticsearch│ │ ELK / Loki  │
   │세션/선점│ │M/Replica│ │ 벡터+검색    │ │ 중앙 로깅    │
   └────────┘ └─────────┘ └─────────────┘ └─────────────┘
```

### 설계 원칙

- **Spring 앱은 완전 무상태(stateless)**. 세션·좌석선점 등 모든 상태를 Redis 등 외부 저장소로 외부화하여, N개 인스턴스가 동일하게 동작하도록 한다. 이것이 분산환경 학습의 출발점이자 전제다.
- 외부 의존(Redis / Elasticsearch / AI / DB)은 **인터페이스로 추상화**하여 도메인 로직과 분리하고 테스트를 격리한다.
- 도메인별 패키지 분리: `auth`, `performance`, `reservation`, `search`, `common`.
- 트랜잭션 경계는 서비스 계층에 둔다.

## 3. 인증/인가 — 세션 + Redis

### 방식

- **Spring Session Data Redis** 사용. `SESSION` 쿠키 기반, 세션 데이터는 Redis에 저장.
- 어느 앱 인스턴스로 요청이 라우팅되어도 동일 세션을 인식 (무상태 앱 + 외부 세션 저장소).
- Spring Security와 통합하여 인증/인가 처리.

### 권한 모델

| 권한 | 설명 | 주요 기능 |
|---|---|---|
| `ROLE_MEMBER` | 일반 사용자 | 공연 검색/조회, 예매, 취소, 리뷰 작성 |
| `ROLE_ORGANIZER` | 주최자 | 공연 등록/수정/삭제, 본인 공연 관리 |
| `ROLE_ADMIN` | 관리자 | 전체 시스템 접근 |

### 비밀번호 해싱

- **BCrypt** 사용 (Spring Security `BCryptPasswordEncoder`).
- 주의: README 초안에는 SHA256으로 기재되어 있으나, 비밀번호 저장에 SHA256은 부적합(빠른 해시 → 무차별 대입에 취약)하므로 **BCrypt로 통일**한다. 이 결정을 README 요구사항에도 반영한다.

### 회원가입/로그인 요구사항

- 이메일/비밀번호 기반 회원가입. 이메일은 고유(unique).
- 로그인 성공 시 세션 생성, 로그아웃 시 세션 무효화.

## 4. 예매 동시성 — 좌석 선점(Hold)

### 좌석 상태 흐름

```
AVAILABLE ──(선점 요청)──▶ HELD ──(결제 확정)──▶ RESERVED
   ▲                        │
   └────(TTL 만료/취소)──────┘
```

### 선점 메커니즘 (채택: Redis SETNX + TTL + DB 유니크 최종 방어)

1. 좌석 선택 → `SET seat:{scheduleId}:{seatId} {userId} NX EX 300`
   - 원자적 연산으로 동시 선점 방지, 5분 TTL로 "일정 시간 후 자동 락 해제" 요구사항 충족.
2. 성공 → 좌석 HELD 처리. 실패 → 이미 선점됨 응답.
3. 결제 확정 → **DB 트랜잭션** 내에서:
   - `tickets(seat_id UNIQUE)` insert (최종 방어선: DB 유니크 제약으로 중복 예매 원천 차단)
   - 좌석 상태 RESERVED로 갱신
   - 예매(reservation) 및 티켓 생성
4. TTL 만료 시 Redis 키 자동 소멸 → 별도 스케줄러 없이 선점 해제.

### 점진적 학습 구현 순서

학습 효과를 위해 다음 순서로 단계적으로 구현한다.

1. **A단계 (비관적 락)**: 단일 DB에서 `SELECT … FOR UPDATE`로 좌석 선점. 동시성 문제와 락의 동작을 직접 재현/관찰.
2. **한계 인식**: 분산(다중 인스턴스) 환경에서 DB 락의 커넥션 점유/확장성 한계 확인.
3. **C단계 (Redis 선점)**: Redis SETNX+TTL 선점으로 개선. 원자성, 자동 만료, 멱등성, 최종 정합성을 학습.

### 검증

- 동시 예매 부하 테스트(예: 다중 스레드/JMeter)로 한 좌석에 단 한 건만 확정되는지 검증.

## 5. AI 자연어 검색 — 벡터 임베딩 시맨틱 검색

### 저장소

- **Elasticsearch `dense_vector` + kNN** 사용. 중앙 로깅에 사용하는 ELK 스택을 재사용하여 인프라를 일원화한다. (대안: Qdrant 등 전용 벡터 DB)

### 임베딩

- **Spring AI + OpenAI `text-embedding-3-small`** (1차 선택, 구현 단순).
- 비용/오프라인 제약 시 로컬 임베딩 모델(ONNX / sentence-transformers 사이드카)로 대체 가능.

### 흐름

1. 공연 등록/수정 시 `title + description`을 임베딩하여 Elasticsearch에 색인.
2. 사용자 자연어 쿼리(예: "주말에 볼만한 잔잔한 분위기의 뮤지컬") → 임베딩 → kNN 유사도 검색.
3. (선택) 카테고리/날짜/가격/별점 등 구조화 필터와 하이브리드 결합.
4. 검색 결과는 페이징 또는 무한 스크롤 중 한 방식으로 제공.

## 6. 분산 인프라 + 로깅

### 구성

- **앱 다중 인스턴스 + Nginx LB**: 무상태성 검증.
- **MySQL Master-Replica**: 쓰기(예매)는 Master, 읽기(검색/조회)는 Replica. Spring `@Transactional(readOnly = true)` 기반 라우팅 학습.
- **중앙 로깅**: 각 앱 로그 → Filebeat/Promtail → ELK 또는 Loki+Grafana로 수집.
- **분산 추적**: `traceId`를 MDC에 담아 인스턴스를 넘나드는 요청을 추적.
- 전체 구성을 `docker-compose`로 묶어 로컬에서 분산 환경을 재현한다.

### (후순위) 모니터링

- Prometheus/Grafana 메트릭 모니터링은 본 단계 범위에서 제외, 추후 확장.

## 7. 데이터 접근 & 도메인 구조

- **MyBatis** 유지 (현 스택).

- 도메인 경계: `auth`, `performance`, `reservation`, `search`, `common`.

## 8. 범위 및 우선순위

### 포함

- 위 4개 학습 영역 전체.
- 공연 등록/수정/삭제, 검색, 좌석 조회, 예매(좌석 선점→확정), 리뷰.

### 후순위 / 단순화
